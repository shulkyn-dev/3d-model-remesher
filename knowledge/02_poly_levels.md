# 02 — Уровни детализации: High / Mid / Low poly и LOD

## Три «поли»-уровня по назначению (НЕ путать с LOD-цепочкой)
- **High-poly** — миллионы полигонов, источник деталей. Из скульпта (ZBrush) или AI-генерации.
  Не идёт в движок напрямую — служит «донором» для бейка нормалей/AO.
- **Mid-poly** — компромисс: достаточно геометрии, чтобы силуэт был хорош без бейка.
  Часто для hard-surface, архвиза, где бейк не нужен.
- **Low-poly** — игровой ассет: минимум полигонов, детали «нарисованы» в normal map с high-poly.

## LOD-цепочка (Level Of Detail) — это другое
LOD0, LOD1, LOD2… — это **варианты ОДНОГО ассета** с уменьшающимся полигонажем, которые движок
переключает по расстоянию до камеры. LOD0 = самый детальный (часто = наш low-poly), дальше грубее.
Цель — производительность: далёкий объект не должен жрать полигоны.

**Важно:** наше «ядро-перестройщик» генерит именно LOD-цепочку из одного входа.

## Типичные правила редукции между LOD
Индустриальный ориентир — каждый следующий LOD ≈ **50% треугольников** предыдущего
(иногда агрессивнее на дальних). Пример цепочки от LOD0:
```
LOD0 100%  →  LOD1 50%  →  LOD2 25%  →  LOD3 12%  →  LOD4 6%
```
Unreal Engine по умолчанию умеет авто-LOD примерно с такими шагами; многие студии задают вручную.
В нашем CLI это: `--levels 0.5,0.25,0.12,0.06`.

## Полигональные бюджеты (ориентиры, треугольники)
Сильно зависят от платформы/движка/важности объекта:
- **Mobile / AR / web (glTF):** герой 5k–20k, окружение 0.5k–3k за объект.
- **PC/Console current-gen:** герой 30k–100k+, проп 1k–10k, фон 0.2k–2k.
- **VR:** жёстче из-за двойного рендера — держать как мобайл/ниже.
- **3D-печать:** полигонаж не важен для качества, важна **watertight**-сетка и достаточная
  плотность для гладкости печати; упрощают, чтобы слайсер не подвисал.

## Texel density (плотность текселей) — связана с уровнями
Сколько пикселей текстуры на единицу поверхности. Должна быть **консистентной** между объектами
сцены (иначе один резкий, другой мыльный). Часто меряют в px/cm. На LOD обычно сохраняют ту же
UV-развёртку → texel density падает естественно с уменьшением модели на экране — это ОК.

## Что это значит для нашего приложения
- Нужны **пресеты** под платформы (mobile/PC/VR/print/web) — это профили `--levels` + метода +
  форматов + (для печати) проверки watertight. → Этап 3 roadmap.
- Стоит считать и показывать **треугольники** (движки считают их, не «полигоны-четырёхугольники») —
  уже делаем через `tri_count()`.
- Для Unreal удобно именование `Name_LOD0/_LOD1...` и сборка всех LOD в один FBX —
  кандидат-фича (сейчас раздельные файлы `_high/_mid/_low`).
